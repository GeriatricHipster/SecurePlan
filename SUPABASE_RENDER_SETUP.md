# Free Supabase + Render launch

SecurePlan uses Supabase PostgreSQL for application data and a private Supabase Storage bucket for floor plans and element photos. The Node service on Render remains responsible for login, permissions, signed file access, and real-time collaboration.

## 1. Create the private Storage bucket

In the Supabase project dashboard:

1. Open **Storage** and choose **New bucket**.
2. Enter `secureplan-files` as the bucket name.
3. Leave **Public bucket** turned off.
4. Set the file-size limit to **50 MB** if the dashboard offers that setting.
5. Create the bucket.

Do not add public access policies. SecurePlan accesses this private bucket only from its server and gives authenticated users short-lived signed download links.

## 2. Collect the three Supabase values

Keep these private; do not paste them into source files or send them in chat.

- `DATABASE_URL`: choose **Connect** in the Supabase dashboard, select the **Session pooler**, and copy its URI. Replace the password placeholder with the database password you chose. If the password contains URL-reserved characters, use the dashboard's correctly encoded connection string or URL-encode those characters.
- `SUPABASE_URL`: open **Project Settings > API** and copy the project URL, such as `https://project-ref.supabase.co`.
- `SUPABASE_SECRET_KEY`: on the same API settings page, copy a server-side **secret** key. A legacy `service_role` key also works. Never use the public/publishable or `anon` key here, and never expose this value in the browser.

## 3. Upload this release to GitHub

Replace the repository contents with this release, then commit and push. Do not upload `.env`, `.env.native`, `data/`, or `.data/`.

## 4. Create the Render Blueprint

1. Sign in to Render and choose **New > Blueprint**.
2. Connect the SecurePlan GitHub repository.
3. Render reads `render.yaml` and creates one **Free** Node web service with no disk.
4. When prompted, enter:
   - `DATABASE_URL`
   - `SUPABASE_URL`
   - `SUPABASE_SECRET_KEY`
   - `SETUP_CODE`: invent a private code at least 16 characters long for the first owner account.
5. Deploy.

`JWT_SECRET` is generated by Render. The bucket name, HTTPS cookies, proxy setting, native app origins, and 50 MB PDF limit are already configured by the Blueprint.

## 5. Verify and create the owner

After the deployment succeeds:

1. Open `https://YOUR-SERVICE.onrender.com/api/health`. Both database and storage should report `ok`.
2. Open the main service URL.
3. Create the first owner account and enter the private `SETUP_CODE` when asked.
4. Create a test site, upload a small PDF, add an element and photo, then reload the page to confirm persistence.

The server creates its PostgreSQL tables and built-in icon profiles automatically on first startup. No SQL-pasting step is required.

## Free-tier behavior

Render Free web services can sleep after inactivity, so the first request after a quiet period can take roughly a minute. The database and uploaded files remain in Supabase when the Render service sleeps or restarts. Review both providers' current free quotas before production use.

## Troubleshooting

- **Database unavailable:** confirm the Session pooler URI is complete, its password placeholder was replaced, and `DATABASE_SSL=true` remains set.
- **Storage unavailable:** confirm the bucket is named exactly `secureplan-files`, is private, and the configured key is a server secret/service-role key.
- **Build fails:** use Node 22 or newer and confirm `package-lock.json` was uploaded with the release.
- **First owner setup is disabled:** ensure `SETUP_CODE` contains at least 16 characters.
- **Native app cannot connect:** keep `MOBILE_ORIGINS=capacitor://localhost,https://localhost` and set `VITE_API_URL` on the native build machine to the Render HTTPS URL.
